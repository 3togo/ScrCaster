# 2026-09-13

## Fixed AGP/Kotlin version mismatch build failure
- Symptom: `./gradlew assembleDebug` failed with "multiple versions of the Android Gradle plugin(9.4.0, 9.3.2)".
- Root cause: miuix submodule was updated to a new commit (`git status` showed "new commits"); main project's `gradle/libs.versions.toml` had drifted from miuix's `agp`/`kotlin`.
- Fix: aligned main project to miuix (source of truth) — `agp = "9.4.0"`, `kotlin = "2.4.20"` in `gradle/libs.versions.toml`.
- Note: `./gradlew` bypasses `build.sh`'s `check_toolkit_versions` guard, so drift isn't caught until Gradle's plugin-resolution error. Prefer `./build.sh` for local Android builds.

## Fixed TV handoff "mobile IP sent but port cannot" (NO_PORT)
- Symptom: in TV receive-address flow, scanning the TV's handoff QR, the phone could not determine its own wireless-debug connect port → `HandoffOutcome.NO_PORT` (IP resolved, port dropped).
- Root cause: `AdbMdnsDiscoverer.discoverService` local-device branch probed `127.0.0.1:port` (`isPortOpened`). A phone's adbd TLS connect service binds to its Wi-Fi IP, not loopback, so the loopback probe "succeeded" (port looked free) and wrongly rejected the live port.
- Fix: in `app/.../nativecore/AdbMdnsDiscoverer.kt`, replaced the loopback `isPortOpened(serviceInfo.port)` check with `isReachableAdbEndpoint(hostAddress, serviceInfo.port)` (matches the existing `requireReachable` path). Removed the now-dead `isPortOpened` + its `ServerSocket`/`IOException` imports.
- `discoverConnectService(includeLanDevices=false)` is only called from `ReceiverHandoff.send`, so the change is scoped to the handoff flow.
